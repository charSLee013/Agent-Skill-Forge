# 裁判设计手册

裁判(judge)是整个循环里唯一被信任的部件。它回答一个问题:**这次变异之后,真实目标变好了多少?** 它必须同时满足三个性质,缺一个循环就会产出特定形态的垃圾:

| 性质 | 缺失时的垃圾形态 |
|---|---|
| **便宜**(比真实研究便宜约两个数量级) | 循环跑不完几个实验,自主性失去意义 |
| **不可收买**(作弊轴被不变性封死) | 分数上涨但真实目标没变好(Goodhart) |
| **单调**(与真实目标同向) | 优化越努力,离用户想要的越远 |

设计顺序固定:先便宜化,再枚举作弊轴,然后逐条封死,最后测噪声地板。

---

## 1. 便宜化:三条正交的降价手段

对"完整评估一次太贵"做分解,每类成本有对应的降价手段:

- **数据太贵 → 采样**:从全集抽有代表性的固定样本(注意"固定"——每轮换样本会毁掉可比性;要旋转见第 3 节)。样本要分层,覆盖难例与易例,比例贴近真实分布。
- **过程太贵 → 缩短 horizon**:真实目标要跑一个月,裁判只跑代表期;要训练到底,裁判只训代理步数。缩短后与真实目标的相关性要抽验过(见第 6 节审计)。
- **人工太贵 → 代理评审**:人类评审换成 LLM 评审 + 规则前置过滤,或换成可计算的代理指标。代理指标与真实评判的一致性要抽样核对,写进裁判方案。

便宜化的目标线:**单次裁判的成本 ≈ 真实评估的 1%**。写不进这个量级的方案,回头重做采样与 horizon 设计,而不是接受一个跑不动的裁判。

## 2. 不可收买:作弊轴枚举与处置谱系

作弊轴的枚举方法是一个换位问题,**逐项写下来,不要在脑子里过**:

> "假如我想不做真工作就把分数抬高,我会怎么做?"

从这几个方向逼问自己:换随机性(种子、采样温度)、蹭评估集(过拟合固定题、背答案)、钻度量定义(单位、归一化、边界条件)、缩工作单元(偷工减料到裁判看不见)、特判(硬编码已知用例)、攻击裁判本体(改裁判代码、喂裁判脏输入)。每个任务写出 5-10 条具体的,然后逐条选择处置:

1. **不变性**:让度量对该轴天然无感。例:目标允许改词表/词元化方案时,用 bits-per-byte 而不是 per-token loss——度量对词表大小不变,这条作弊轴整根消失。这是首选处置,能设计出不变性就不用守门。
2. **地板**:给该轴的波动留噪声余量,波动小于余量视为平局(见第 4 节)。
3. **旋转**:让该轴没有固定目标可蹭(见第 3 节)。
4. **封存**:裁判代码、评估数据、协议进入冻结集,版本化,只有人类能改。执行者发现裁判有漏洞时的唯一合法动作是停下报告。
5. **红队**:独立地专门派一次"不择手段拿高分"的攻击运行(用另一个上下文,不给它本循环的改进目标,只给裁判和分数)。攻击成功 = 裁判出一个补丁版本。成本允许时,循环开始前攻击一次,此后每几十个实验再攻击一次。

每条作弊轴必须落到这五种处置之一;落不进去的作弊轴就是裁判的已知漏洞,要么补设计,要么在宪法里向用户声明接受该风险。

## 3. 旋转评估:不给过拟合留固定靶子

固定评估集是"换种子式改进"得以存活的一半原因(另一半是没有噪声地板)。旋转的做法:

- 准备一个 held-out 题池(不参与任何开发、调试、可视化)。
- 每次裁判从题池随机抽题,或按实验序号轮换固定子集。
- 抽样比例与分层方式写进裁判协议(冻结集的一部分),执行者无权调整。

保留一个极小的固定锚集(3-5 题)用于跨实验的可比性校准是可以的;锚集只用于报告,不用于 keep/discard 判定。

## 4. 噪声地板:把"换运气"挡在选择压力之外

流程固定,不可跳过:

1. 基线不改任何代码,重复跑 k 次(k ≥ 5,随机性大的任务加到 10+)。
2. 记录 k 次分数的均值 μ 与标准差 σ。
3. 地板 = 2σ(或凭任务性质取 3σ)。选择压力规则:提升 ≥ 地板才算 keep;|变化| < 地板一律平局,discard。

注意:σ 大到淹没任务预期的合理提升量时,裁判本身不合格,回第 1 节重新便宜化(通常意味着样本太少或 horizon 太短),而不是把地板放宽到毫无意义。

## 5. 度量形态:门槛化与字典序

平滑的连续标量奖励小碎步(每步蹭一点点)。两种改造:

- **门槛化**:只认跨过定性 bar 的变异——"在更难的分布上也赢""同等精度下延迟减半"。跨过 = keep,没跨过 = 平局,不论标量涨了多少。
- **字典序**:主指标定胜负;平局时才比第二键。第二键几乎总该是**简约**:机制更少、代码更短者胜。这条让"删代码的等价提升"成为合法且受奖励的变异,是抵抗无聊轴聚集的隐性力量。

两条例子(看推理形状,不抄结论):

- 例一(门槛化的推理):视频转码任务的原始标量是平均码率。枚举作弊轴时发现"降分辨率可以无限压码率"——标量本身对画质不设防。处置:门槛化,画一条"主观质量抽检不低于基线"的 bar,bar 之下码率再低也是平局。
- 例二(字典序的推理):两个变异都把错误率从 5% 降到 4.5%。一个加了一段启发式补丁,另一个删掉了 40 行死代码。字典序下后者胜——不是因为分高,而是因为主指标平局时机制更少者胜。

## 6. 裁判的治理:它自己也是被审计的对象

裁判会随任务理解加深而显出缺陷,治理规则固定:

- **版本化**:裁判方案与实现带版本号;每次修补记录"堵了哪条作弊轴、动了哪些行"。
- **人类独占修补权**:执行者发现可刷分漏洞 → 暂停 → 报告 → 等人类出补丁。漏洞存续期间的分数全部作废,不追溯采信。
- **周期审计**:每隔一段(或每 N 个 keep)做两件事:红队攻击一次;人类从保留变异里抽样,核对其在**真实目标**(而非代理指标)上是否成立。审计发现代理失真 → 修补代理,失真期间的结论降级为"存疑"。

## 设计完成的自查清单

- [ ] 单次裁判成本 ≤ 真实评估的约 1%,数字写进了方案
- [ ] 作弊轴清单 ≥ 5 条,每条落在五种处置之一
- [ ] held-out 题池存在且旋转方式写进协议;固定锚集(若有)不参与 keep/discard 判定
- [ ] 噪声地板来自 ≥ 5 次基线实测;地板小于任务预期的合理最小提升
- [ ] 度量形态明确(标量/门槛化/字典序),第二键(若用字典序)是简约
- [ ] 裁判版本号、修补流程、审计节奏写进了宪法

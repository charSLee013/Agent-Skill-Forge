# 分支手册:三类任务的裁判与变异面(推理形状展示)

本手册展示三类常见任务各自"一个实验是什么、作弊轴长什么样"。**这里的例子是推理过程的展示,不是答案库**(SKILL.md 防抄条款):每个例子只演示"如何从任务出发枚举作弊轴、为何选择该处置",你面对的任务哪怕与例子同类,作弊轴也会不同,必须自己重新枚举。自查方法见各节末尾。

---

## 分支一:代码性能优化

**任务形态**:把某个东西变快/变省(吞吐、延迟、内存),同时正确性不许动。

**一个实验 = 一次代码变异 + 一次计时/计量**。

**推理示例**(解析器提速类任务,演示作弊轴如何被枚举出来):

> 换位提问:"想不真提速而让计时数字变小,我会怎么做?" → ①把输入变小/变简单 ②把冷启动开销挪出计时区 ③缓存上次的输出 ④砍掉难缠的边角处理 ⑤悄悄降低输出完整度。
> 逐条找处置:①→不变性(评估输入从语料池分层抽样并封存);②→协议封存(计时起止点写进协议);③④⑤→同源,输出等价性检查能一次封住三条(变异前后输出逐字节一致,或按任务定义的等价关系一致)。
> 剩下的轴是硬件与运气 → 噪声地板(同机多次取中位数,地板取波动幅度)。

**变异面在性能分支的典型样貌**:算法与数据结构、并发结构、内存布局、预计算、I/O 模式全部开放;输入语料、计时协议、输出基线冻结。

**退化信号**:保留变异的描述集中在"又调了一个 batch/线程数"→ 无聊轴黑名单该加了;产出"理论上更快、实测平局"的变异扎堆 → 怀疑计时协议分辨率不足,回裁判设计。

**自查**:你的等价性检查挡住了哪条作弊轴?答不出"哪条"就说明是抄来的。

## 分支二:Prompt / Agent 程序进化

**任务形态**:改进一个由指令(prompt)+ 控制流组成的程序,让它在某类任务上更可靠。变异面是提示词文件与编排代码本身——它们就是"代码",照常适用"变异面开放"原则。

**一个实验 = 一次程序变异 + 在 held-out 任务套件上跑一次完整评测**。

**推理示例**(分类指令优化类任务,演示评测套件如何防收买):

> 换位提问:"想让 pass rate 涨而不真变强,我会怎么做?" → ①把评测题背下来写进指令 ②针对每道题打补丁式特判 ③输出格式上讨好评分器 ④只做对容易题,难题躺平 ⑤调温度/种子蹭运气。
> 逐条:①→不变性(held-out 题池从真实失败分布另采,任何开发环节不可见;旋转见 judge-design §3);②→题池够大且每次抽题,特判成本高于收益;③→评分器与格式解耦(评分先做内容等价归一);④→分层配额(难例占比写进协议);⑤→噪声地板照旧。
> 洞见:这类任务里"评测套件的来源分布"决定了进化方向——题池采错了,进化就在优化一个不存在的产品。题池设计是本分支裁判工作的大头,值得花掉一半以上的设计时间。

**变异面在 Agent 分支的典型样貌**:指令文本、few-shot 选取逻辑、工具调用编排、错误恢复路径全部开放;题池、评分器、协议冻结。

**退化信号**:保留变异是"在指令里加了一句针对性叮嘱"的堆积 → 提示词膨胀,简约准则该上场了(指令长度做字典序第二键);keep-rate 趋零 → 题池分布与真实失败分布脱节,回裁判设计。

**自查**:你的题池采样自哪个分布?与用户说的"真实失败场景"是否同源?

## 分支三:算法 / 数据配方发现

**任务形态**:寻找一个配方(算法参数之上的结构选择、数据配比、规则组合),在代理评估上找方向,最终在真实目标上兑现。

**一个实验 = 一次配方变异 + 一次代理评估**。

**推理示例**(数据混合配方类任务,演示代理与真实之间的鸿沟如何设防):

> 换位提问:"想让代理分涨而不真变好,我会怎么做?" → ①过拟合代理评估集 ②选中在代理训练的固定种子下偶然占优的配方 ③钻代理指标的空子(代理任务的偏置) ④用未来信息泄漏(配比搜索阶段反复见过评估数据)。
> 逐条:①→旋转评估 + held-out 终验(胜出配方最后必须在从未参与搜索的数据上复验,复验不过 = 全线存疑);②→胜出配方需在 ≥ 3 个种子下复验取中位数;③→代理任务与真实任务的分歧单独成轴,抽验一致性;④→流程级封存(搜索流水线与终验数据物理隔离)。
> 洞见:本分支的特殊结构是"两级裁判"——便宜代理负责指引方向,昂贵的终验负责兑现;代理只拥有提名权,没有决定权。把决定权交给便宜代理,是这个分支最常见的事故来源。

**变异面在本分支的典型样貌**:配方生成逻辑、配比搜索代码、代理训练脚本全部开放;终验数据、终验协议、代理评估集冻结。

**退化信号**:代理分一路涨、终验不动或倒退 → 代理失真,立即回裁判治理(而不是继续榨代理分);保留配方全部是"某一维比例微调" → 无聊轴,变异组合配额该轮换了。

**自查**:你的代理与真实目标的一致性抽验过吗?"代理说好、真实也好"这句话目前的证据是什么?

## 跨分支通用的两条

1. 三个分支的例子都演示了同一件事:**先换位枚举作弊路径,再让每条路径撞上一个处置**。顺序不能反——先选度量再找漏洞,漏洞永远找不完;先列漏洞再定度量,度量一次成型。
2. 例子里的处置(等价性检查、题池旋转、两级裁判)是**处置谱系**的实例。你的任务很可能需要谱系里的另一件武器:回到 `judge-design.md` §2 的五选项,而不是照搬例子。

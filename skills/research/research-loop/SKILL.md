# research-loop

先读这一节再动手。本 skill 的灵魂是一个等式:

> **自主研究循环 = 开放的代码变异面 ⊕ 便宜可信的裁判 ⊕ 选择压力(验收规则)。**
> 产出物的形态由裁判的不变性和验收规则决定,而不是由执行者的意图决定。

从这个等式推出三条纪律,全文的每个步骤都在落实它们:

1. **裁判是地基**。裁判必须便宜(比真实研究便宜约两个数量级)、不可收买(作弊轴被不变性封死)、且随时间可治理(版本化 + 人工审计)。裁判被污染的那一刻,循环的产出全部作废。
2. **冻结集只包含信任**。被保护的东西 = 裁判代码 + 它读取的地面真相(评估数据、评估协议、必要种子),仅此而已。边界画在信任周围,不画在便利周围;边界之外的构建系统、配置、目录结构、工具链全部显式声明开放。
3. **变异面是代码,不是参数网格**。超参只是代码的投影。允许执行者直接增删改代码,"超参"这个概念就被溶解了;把搜索空间写死成一张参数表,循环必然退化成调参。

最后一条心法:**退化成调参不是模型缺陷,是制度设计的结局。** 选择压力奖励安全的小碎步,执行者就会走小碎步;抑制的方式是修改裁判的不变性和验收规则,不是祈祷执行者勇敢。Phase C 的退化诊断和宪法修补就是为此存在的。

## 防抄条款(对执行者有约束力)

`references/branches.md` 里的示例是**思维形状的展示,不是答案库**。即使当前任务与某个示例高度相似,也必须从零执行作弊轴枚举与裁判设计。把示例中的裁判、门槛数值、变异面直接搬到新任务上是违规——因为答案可以抄,不变性不能抄:不同任务的作弊轴不同,抄来的裁判挡不住新的作弊路径。自查方法:设计文稿里的每一条裁判规则,都应该能回答"它挡的是本任务的哪条作弊轴",答不出来就说明是抄的。

## 三阶段总览

| 阶段 | 产出 | 是否需要用户参与 |
|---|---|---|
| A 设计 | 裁判方案 + 变异面边界 + 宪法全文 | **必须**:确认门槛,不确认不执行 |
| B 执行 | 账本 + git 分支上的保留变异 | 仅在熔断、裁判漏洞、用户早停时 |
| C 汇报 | 改进排序 + 退化诊断 + 宪法修补建议 | 是:人工抽检保留变异 |

## Phase A:设计(每次运行必经,顺序执行)

### A1. 访谈目标

弄清三件事,缺一项就追问用户:

1. **真实目标**:什么在真实世界里算"变好"?方向是什么(更高/更低/达标即可)?
2. **真实成本**:完整评估一次为什么贵?贵的根源是数据、算力、时间还是人工?——便宜的裁判就从"能否采样、能否缩短、能否代理"这三个方向造。
3. **约束与预算**:一次实验允许消耗多少(时间/token/算力)?有哪些硬约束(不许改的依赖、输出格式、合规)?

完成判据:能用一段话向用户复述"好/贵/约束",用户认可。

### A2. 枚举作弊轴

换位提问:**"假如我想不做真工作就把分数抬高,我会怎么做?"** 对本项目列出 5-10 条具体路径(换种子、过拟合固定评估集、钻度量定义的空子、缩短工作单元、特判已知用例、直接改裁判代码……)。

每条作弊轴都必须在 A3 里有一个对应处置,枚举完先自查一遍这个对应关系。

读 `references/judge-design.md`(作弊轴枚举方法与处置谱系),再读 `references/branches.md` 里对应分支的推理示例(记住防抄条款:学它的思路,不抄它的结论)。

完成判据:作弊轴清单成文,每条标注了拟采用的处置方式。

### A3. 设计裁判

按 `references/judge-design.md` 落实,产出裁判方案:

- **度量**:主指标是什么、方向如何;必要时用门槛化(只认跨过定性 bar)或字典序(主指标定胜负,平局才比简约)。
- **噪声地板**:先跑基线 k 次,给出分布与地板值(如"提升 < 2σ 视为平局")。没有噪声地板的选择压力会把"换随机种子"当改进保留。
- **不变性设计**:每条作弊轴 → 一种处置(度量对该轴不变 / 旋转评估集 / 封存裁判代码 / 红队攻击)。
- **成本**:单次裁判耗时/花费必须比真实研究便宜约两个数量级,写明数字。

完成判据:裁判方案成文,覆盖 A2 全部作弊轴,噪声地板有实测来源。

### A4. 划变异面

写清两份清单:

- **冻结集**:裁判代码、地面真相、评估协议、必要种子。逐个列出路径。修改冻结集 = 违规,唯一的合法路径是"报告人类 → 人类修补 → 裁判版本 +1"。
- **开放面**:除冻结集外的一切,显式声明开放(包括构建系统、配置、目录结构)。执行者不敢改的东西往往不是不能改,而是没被授权——把授权写成白纸黑字。

完成判据:两份清单都有具体路径,开放面里没有任何"懒得说明所以先禁了"的条目。

### A5. 写宪法

用 `references/constitution-template.md` 填空成文。三个模板条款必须逐条与用户过目,不允许静默采用默认值:

1. **运行策略**:默认 NEVER STOP(跑到手动打断,不问"要继续吗"),或用户设置的早停参数(实验数上限 / 墙钟上限 / 熔断:连续 N 次无保留 → 停下报告"地形或裁判可能坏了")。
2. **探索预算**(对付"短期降、长期好"):每 N 个实验允许 1 次 wild mutation——大结构改动允许暂时回撤,记在侧分支上不参与主线 advance-or-reset,后续验证是增益方向才并回。
3. **反调参条款**(对付"短期升、长期差"与平庸化):无聊轴黑名单(未来 M 个实验禁碰的旋钮类改动)、变异组合配额(架构/算法/数据/目标轮流开采)、新颖性约束(与最近 K 个保留变异雷同的方案按平局处理)、简约准则(等价结果取更少机制,删代码的等价提升必须保留)。

完成判据:宪法全文成文,上述三条逐条经用户过目。

### A6. 确认门槛(硬性,不可跳过)

向用户完整呈现:裁判方案、冻结集与开放面清单、宪法全文、以及**早停选项菜单**(默认 NEVER STOP;可选实验数上限、墙钟上限、熔断条件,用户设了就优先生效)。

得到用户的明确确认后才进入 Phase B。用户调整了任何条款,改完宪法再确认一次。

完成判据:用户明确说"确认/开始"。

## Phase B:执行

初始化(一次性):

1. 从主线切出研究分支:`git checkout -b research/<日期-标签>`。
2. 建账本文件(如 `results.tsv`),并确认它在 `.gitignore` 里——账本不进 git,回滚不能撕毁历史。
3. 首个实验固定为基线:不改任何代码跑一次裁判,把结果记为第一行。

循环(永久重复,直到运行策略触发停止或用户打断):

1. 在 `train` 思路上选一个变异:直接修改开放面里的代码。优先从变异组合配额的当前轮次类别里取想法。
2. `git commit`(一个 commit = 一次变异,描述写进 commit message)。
3. 跑一次裁判,结果只追加进账本(status 取 keep / discard / crash)。
4. **选择压力**:提升 ≥ 噪声地板 → keep,分支前进;否则 → discard,`git reset` 回分支起点。crash 的处置:笔误型缺陷(路径错、漏 import)修复后重跑一次;想法本身破产的,记账后放弃。
5. 探索预算轮次:允许 wild mutation 落在侧分支,即使分数暂时回撤也不 reset,验证其方向后再决定并回或废弃。

执行纪律:

- 全程不碰冻结集;发现裁判漏洞(有分可刷)→ 立即暂停执行,向用户报告漏洞细节,等人类修补并升级裁判版本后继续。期间产生的分数一律作废。
- 不向用户请示"要继续吗"——这是宪法里 NEVER STOP 的含义;会打断循环的只有:运行策略触发、熔断条件命中、裁判漏洞、用户手动打断。
- 每完成约 10 个实验,向用户做一次一行式进度播报(当前最优、keep-rate、账本行数),播报不打断循环。

完成判据:触发停止条件时,账本行数、分支 commit 历史与账本一一对应,无未记录的实验。

## Phase C:汇报与治理

按顺序交付:

1. **账本**:全部实验的追加记录。
2. **保留改进排序**:按每次保留变异带来的 delta 降序,标注累计提升。
3. **退化诊断**,三个信号各给结论:
   - 保留变异的描述是否聚集在无聊轴上(是 → 建议加严无聊轴黑名单);
   - keep-rate 是否趋近于零(是 → 怀疑裁判噪声过大或地形已采尽,建议重测噪声地板);
   - crash 是否占主导(是 → 变异面太脆,建议在裁判前加冒烟检查)。
4. **保留变异抽检包**:挑出 delta 最大的 k 条与 delta 最可疑(贴着噪声地板)的 k 条,附上下文供用户人工核对"真实目标是否真的变好了"——这是防 Goodhart 的最后一道人工工序。
5. **宪法修补建议**:把本次观察到的制度缺陷写成对模板条款的具体修改,供下一次运行的 meta 循环使用。人类迭代的是宪法和裁判,不是单个实验。

完成判据:五项交付齐备,抽检包和修补建议具体到条款。
